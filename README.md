# Bank Classifier MLflow Demo

## Project Overview
This project demonstrates a complete machine learning workflow for a bank marketing classifier using FastAPI, MLflow, PyTorch, and Docker. It covers data ingestion, model training, experiment tracking, and serving predictions via a REST API.

## Dataset & Task
The task is binary classification: predict whether a bank customer will subscribe to a term deposit (`y`) as the outcome of a direct marketing campaign conducted via phone calls. This is the classic "Bank Marketing" problem — each row is one customer contacted during a campaign, described by:
- **Demographic/financial attributes:** `age`, `job`, `marital` status, `education`, `default` (has credit in default?), `balance` (average yearly balance), `housing` and `loan` (housing/personal loan status).
- **Campaign-contact attributes:** `contact` type, `day`/`month` of last contact, `campaign` (number of contacts made this campaign), `previous` (contacts made before this campaign), and `poutcome` (outcome of the previous campaign). See `CustomerFeatures` in `src/main.py` for the exact schema and allowed categorical values.

Two raw columns are intentionally dropped before feature engineering (`process_features` in `src/utilities/utils.py`): `duration` (the last call's duration in seconds — excluded because it's only known *after* a call ends, making it a leakage feature for a model meant to predict before contacting someone) and `pdays` (days since a previous contact).

The class distribution is heavily imbalanced: a local training run against `bank_schema.train` (750,000 rows total, split 600,000/150,000 for train/validation) showed 527,671 negative vs. 72,329 positive examples — roughly 88% did not subscribe. `bank_classifier.py` compensates for this with a `pos_weight` term (~7.3) in `BCEWithLogitsLoss`.

## Key Features
- **Data Ingestion:** Bank marketing data is uploaded to MinIO manually (see [Loading data into MinIO](#loading-data-into-minio)), then loaded into DuckLake via `src/db_loader.py`.
- **DuckLake Integration:** Implements DuckLake for accelerated data querying and efficient data access during preprocessing and feature engineering.
- **Model Training:** Trains a neural network classifier using PyTorch, with hyperparameter optimization via Optuna.
- **Experiment Tracking:** Uses MLflow to log metrics, parameters, and model artifacts for reproducibility.
- **Model Serving:** Serves predictions through a FastAPI REST API, supporting both raw feature input and one-hot encoded features.
- **Dockerized Environment:** Includes Docker and docker-compose for easy local deployment and isolation.

## API Endpoints
- `GET /`: Welcome message.
- `GET /health`: Health check with UTC timestamp.
- `POST /get_features`: Accepts a list of raw features, returns a dictionary of processed (one-hot encoded) features for model input.
- `POST /predict`: Accepts a JSON dictionary of model input features, returns the prediction.

## Folder Structure
- `src/`: Source code for API, model, utilities, and prediction logic

## Local setup: one-time hosts file entry
`src/bank_classifier.py` registers the trained model with MLflow, which uploads the model artifact directly to MinIO using a presigned URL. That URL is generated by the `tracking_server` container using its internal Docker hostname for MinIO (`minio`), which your host machine can't resolve on its own — even though `src/bank_classifier.py` itself runs locally (outside Docker) and connects to the tracking server fine. Map that hostname to your machine once, and it'll resolve correctly for the lifetime of your local setup:

```
echo "127.0.0.1 minio" | sudo tee -a /etc/hosts
```

(On Windows, add the equivalent line `127.0.0.1 minio` to `C:\Windows\System32\drivers\etc\hosts`.) Without this, `mlflow.pytorch.log_model(...)` in `bank_classifier.py` will hang retrying failed artifact uploads.

## Loading data into MinIO
`train.csv` and `test.csv` are not committed to the repo or read from a local folder automatically — upload them to MinIO manually before running `src/db_loader.py`.

1. Start the stack so MinIO is running: `docker compose up -d minio`
2. Open the MinIO console at [http://localhost:9001](http://localhost:9001) (login with `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` from `.env`, default `admin` / `password`).
3. Create the bucket named in `MINIO_BUCKET` (default `bank-marketting-data`) if it doesn't exist.
4. Inside that bucket, create a folder named `MINIO_DATA_FOLDER` (default `data`) and upload `train.csv` and `test.csv` into it, so the objects are `data/train.csv` and `data/test.csv`.

   Alternatively, using the [MinIO Client (`mc`)](https://min.io/docs/minio/linux/reference/minio-mc.html):
   ```
   mc alias set local http://localhost:9000 admin password
   mc mb local/bank-marketting-data
   mc cp train.csv local/bank-marketting-data/data/train.csv
   mc cp test.csv local/bank-marketting-data/data/test.csv
   ```
5. Run `python src/db_loader.py` to load the CSVs from MinIO into the local DuckLake catalog (`bank_schema.train` / `bank_schema.test`).

MLflow also needs its own bucket, `mlflow-artifacts`, to store logged models (separate from the data bucket above — configured in `docker-compose.yml`'s `tracking_server` command, not via `.env`). Create it once via the MinIO console or `mc mb local/mlflow-artifacts`, before running `src/bank_classifier.py` — otherwise `mlflow.pytorch.log_model(...)` fails with `NoSuchBucket`.
